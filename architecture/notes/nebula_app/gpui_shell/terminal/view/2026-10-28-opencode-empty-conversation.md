# OpenCode 空白新会话的预览清理

## Status

实现并回归；阶段验证见 [路线图](../../../../../../ROADMAP.md)。

## Context

OpenCode 2.1.2 执行 `/new` 后进入无 ID 的空白页。等到第一条消息入队才创建原生会话，
服务器桥因而不能在空白页提供新 ID。仅按 ID 更新会让上一会话的预览残留。

## Evidence

真实本机 CLI 与隔离产品的 Runtime 共同复现：原生页面已经回到 Logo 与编辑器，
桥接会话 ID 和上一条已接受预览仍保留。安装版本内的 `session.viewed` 事件仍要求
已有 `sessionID`，不能把它解释为无 ID 的新页面。
进一步采样原生事件确认，新输入确实产生新的 session.created 和用户入队事件。
旧桥没有进程实例标记；当内核解析不到 Agent PID 时，共享生命周期按安全合同拒绝
跨会话 SessionStart，因此新正文仍被拒绝。带固定 PID 的原单测没有覆盖这条失败路径。

## Decision

[预览适配器](../../../../../../nebula_app/src/gpui_shell/terminal/view/input_preview.rs)只在
OpenCode 空闲且首页 Logo、编辑器页脚稳定出现两秒时清除旧正文。
屏幕仅作为保守失效信号，不提取正文、不生成会话 ID、不修改恢复目标或 Agent 生命周期。
新正文仍须由确认的用户入队事件发布，新 ID 沿用已有所有权边界。
OpenCode 桥沿用 Pi 的实例边界：每次桥初始化生成 UUID，同一串行发送链保留它及递增序号。
没有解析到 PID 时，只有同一桥实例的 SessionStart 可替换会话；有明确 PID 冲突时仍拒绝。
跨会话去重和乱序门按该实例归并，旧序号不能把会话切回去。客户端内核进程树校验继续保留。

## Rejected alternatives

- 沿用旧预览直到新 ID 出现：空白会话仍显示其他对话的内容。
- 直接把 `/new` 键盘输入当作成功：命令可能仍在草稿或被 CLI 拒绝。
- 从首页提取输入正文：草稿没有提交证据。
- 单帧 Logo 立即清除：接受输入与页面重绘之间存在正常过渡。

## Consequences

首页结构变化或极窄视口需重新核对失效探针；它不会授权任何新的正文。
同目录并行会话仍不能用 cwd 或最近更新时间绑定。

## Validation

回归覆盖单帧不清除、稳定首页清除、新会话的可靠用户事件恢复正文，以及缺少 Logo
或编辑器页脚的负例。真实 CLI 再验收另行记录。
新增无 Agent PID 的真实失败回归，覆盖同实例替换、外来实例拒绝及旧会话迟到事件。

## Supersedes

None。

## Revisit when

OpenCode 提供绑定前台客户端的无 ID 新会话事件，或首页呈现合同变化时。
